# 段评选区契约

新建喜欢或段评要求同一原始段落内可可靠映射的纯文本，至少 5 个 UTF-16 单位。不同原始段落、带格式或无法映射的范围不提交，并给出提示；复制和全选不受五字门槛限制。

## 定位与请求

- HRM 使用 `MarkdownSelectionInfo.ranges`；提椠使用 `CjkSelectionState.selectedRanges` 与既有 Markdown 片段键映射。
- 原始选区必须属于同一个服务端 PID；换行或多个显示块不等于跨原始段落。显示块按转换器身份定位，逐块验证连续性和文本，不能把不同 PID 或多个独立同名 PID 合并。
- 偏移为 UTF-16 半开区间；`br` 按真实正文与服务端 `segment_infos.text` 配对中的 LF 保留，不能当作零长度。未验证的嵌套块分隔规则不猜测。重复文字按实际区间定位，不取首次字符串匹配。
- 已有真实段落的首个 U+200B 在段评文本中对应 U+0020。该等长映射必须保留原来的一位偏移，不扩展为任意位置的零宽字符删除、空白折叠或 NBSP 归一化。
- 已有划线展开到显示选区时也要转换偏移，不能直接套用源段落偏移。已有划线的喜欢／取消喜欢按原标识执行，不因旧引文短于五字而无法取消。
- 所选字符来自未格式化文本节点；已有段评高亮只是交互标注，不把加粗、链接、公式等洗成纯文本。转换时丢失格式信息的段落不能误判为纯文本。
- 新建通过校验后调用既有 `createSegmentReactions`，界面及请求入口均保留五字检查。HTTP 失败、空响应和无授权不能报告成功；取消异常继续传播。错误提示由正文所属页面持有，不能随选区菜单关闭而丢失。

## 已有跨段划线

官方 Android 的普通选区新建与既有跨段 mark 是两条链路。前者把起止 PID 设为当前原始段落；后者按同一划线标识汇集各段真实切片。不得把服务端支持独立起止 PID 的序列化结构，当作任意跨段新建已经验证。

- 点击或选择已有划线后，喜欢和评论复用它的 `segment_id`。已有跨段喜欢只发送标识，不附带某一段的伪造起止坐标。
- 已有段评发布以 `segment.segment_id` 定位，不重复按引文创建；引用全文用于显示。段间展示换行不计入已有划线的原段坐标。
- 跨段 mark 的原文按正文顺序连接各段切片；展示可保留段间空行。打开已有评论不先喜欢、取消喜欢或新建划线。

## 计数

评论增删按实际请求客户端和正文类型/ID 隔离。详情请求捕获累计增量水位，仅随成功正文发布；显示时叠加水位之后的增量，失败保留旧快照。成功才增减计数，普通评论不触发段评事件。

旧跨段 ID 一次操作只记首个 ID，读取去重。不猜测根评论删除的级联数量；没有服务端因果版本时不声称服务端强一致。

## 验证

复用同段定位、重复文字、格式边界和请求体用例。单字仍可用于验证映射精度，但不足五字不能发送新建请求；五字阈值按 `String.length` 校验，不能误换成 Unicode 码点数。跨不同 PID、链接、图片、公式、代码等范围不发创建请求；同 PID 内连续换行保留其原文和偏移。获准读取真实页面时，按实际响应核对字段存在性与分段；不自动发送评论或喜欢。
