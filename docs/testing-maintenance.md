# 测试维护方法

默认复用已有测试和实际页面验收。只有覆盖缺失且保护独立必要的长期行为时，才向现有套件最小追加，随功能或修复进入同一 PR；不为取证增加生产 helper、注入层或常驻截图套件。

## 覆盖取舍

- 解析、模型映射、URL/请求构造和状态转换优先放在已有 common/JVM 套件；窗口、生命周期、系统栏、输入/手势、保存恢复、可访问性和平台服务才需要设备。
- 同一契约的重复用例可合并或由至少同样强的覆盖替代；不依赖设备的逻辑迁入已有 common/JVM 套件并复用夹具。
- 仅检查文件存在、非空、常量或实现结构，已被消费者或更强行为覆盖，或产品行为已移除的用例可删除。覆盖等价性不清时先保留。
- 修改或删除前读目标断言。名称、年代、运行慢、不稳定或有无 issue/PR 都不能单独决定取舍；来源只用于核对行为，不另建逐用例台账。

## 取证与验证

- 临时复现、截图、抓包和性能取证放在仓库外的隔离验证树，保留基线与待验证 SHA、临时改动、命令和实际结果；不改写长期测试，不提交临时源码、原始响应、凭据或输出。
- 只执行最小相关检查，不默认跑全量设备或多变体矩阵，不扩大用户给定预算。必要且成本合理时取得一次修复前失败与修复后通过，复用已有结果；删除冗余用例以 diff 和必要编译验收。
- 界面改动仍须验收真实目标状态。截图文件存在、脚本退出或编译成功不代表行为通过；必要的长期像素断言在内存验证。响应样本不代替重复请求、负载或竞态的实际操作。
- 按 [PR 模板](../.github/PULL_REQUEST_TEMPLATE.md) 报告取舍、替代覆盖和实际验证；网络、设备、编译或 CI 未完成时如实说明。
- 测试取舍作为可审阅的改动进入 PR；CI 只运行已提交的测试，不自动修改、删除、搬迁或隔离测试源码。
- PR 仅修改允许的说明文档时不运行重验证；仅修改 `app/src/androidTest/` 时运行格式、测试 APK 构建及设备分片。手动执行、混合改动和未知路径走完整检查。聚合门禁只接受计划内任务成功和无关任务跳过，路径判定失败不能放行。
