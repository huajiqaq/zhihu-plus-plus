# 测试维护方法

## 长期回归与新增

默认不新增测试。图标恢复、文案、颜色和布局校准等界面修复优先复用已有检查和实际页面验收，不因本次修复就新增常驻像素测试或截图套件。只有改动容易回归、现有覆盖缺失，并且保护独立必要的行为契约时，才向现有套件最小追加；已有覆盖足够时不新增。长期回归随功能或修复进入同一 PR，不为每次修复新建文件、复制平台矩阵或增加一次性生产 helper、注入层。

选择能证明行为的最小执行面：纯解析、模型映射、URL/请求构造和状态转换优先使用已有 common/JVM 测试；只有确需平台行为时才使用设备。

## 设备用例取舍

每个候选核对：保护什么长期行为、现有覆盖为何不够、为何必须 Android 执行。

| 取舍 | 判断 |
| --- | --- |
| 保留 | 确需设备的窗口、生命周期、系统栏、输入/手势、保存恢复、可访问性或服务集成，保护独立的用户行为、数据或安全契约。 |
| 合并 | 同一契约和路径重复时保留至少同样强的覆盖，不把无关问题塞成巨大用例。真实回归也可由更强等价覆盖替代。 |
| 迁移 | 有长期价值但不依赖设备的逻辑整合到已有 common/JVM 套件，复用夹具。 |
| 删除 | 仅验证截图文件、非空、前缀、常量或实现结构；只测夹具或转发函数且消费者已覆盖；无独立契约的临时确认、已被更强行为覆盖的用例，或产品行为已移除。 |
| 待核对 | 行为或覆盖等价性不清先保留并说明缺少的证据，不算已审完。 |

名称、年代、运行慢、不稳定或曾修复过一次都不是单独的取舍依据。像素断言只有保护独立必要的长期行为时才常驻，并在内存验证，不以截图文件存在代替。

## 临时取证

临时复现、截图和性能取证在仓库外的隔离验证树中进行。记录对应的基线及待验证 SHA、附加的临时改动、命令与实际结果，便于复查；临时测试源码、抓包和输出不进入功能 PR，也不改写工作树中的长期测试。发现独立长期契约时，将行为断言整合到已有套件，而不是把整套取证工具搬入仓库。

## 按比例验证

- 默认不跑全量设备测试，只执行最小相关用例；用户限制验证预算时不扩大执行面。
- 真实回归缺乏证据且成本合理时取得一次修复前失败和修复后通过，复用已有结果，不反复恢复基线、重建多变体。
- 删除完全冗余用例以差异审查和必要编译验收，不为删除重跑全部被删用例。
- 网络、设备、CI 或编译检查未完成时如实说明；跳过、脚本退出或截图非空不算行为通过。
- 「不新增测试」不等于用编译代替界面验收。素材应来自实际目标状态；录屏核对开始、操作与结束，无效素材先撤下，不制作占位演示。
- 真实响应只能证明数据链路；重复请求、负载或竞态必须由对应操作证明，不能拿样本本身当回归结果。

## 合并前检查

修改或删除前读目标断言，保护其他工作树改动。审查长期契约、执行面、取舍理由、重复或替代覆盖及实际验证，不为形式逐文件全文读取或重跑全套测试。

来源可为产品契约、协议样本、真实 issue/PR 或提交，用于核对行为，不是保留或删除依据；有无 source issue 均不能单独决定取舍。不要求同时有 issue 和 PR URL，不补造链接，也不另建逐用例台账。验证内容按 [PR 模板](../.github/PULL_REQUEST_TEMPLATE.md) 报告，未执行的检查如实说明。

CI 只运行和检查已提交的测试，不自动写入、删除、搬迁或隔离测试源码。反对在合并时自动删除回归测试；测试取舍必须作为可审阅的改动进入 PR。
