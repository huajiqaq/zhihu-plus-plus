# 知乎功能与协议验证

先确认交付物是协议说明还是仓库实现，以及用户允许的执行面。第三方建议只作线索，不能从 UI 需求猜后端字段、action 或数据库结构。

## 行为与来源

- 写清入口、操作、成功状态、返回后保留什么，以及非目标。复用已有协议证据，不默认另建长期账本。
- Web 能完整覆盖时使用独立浏览器上下文；已知协议直接重放请求。Android 只补移动端特有入口、灰度或协议，记录官方版本和路径。
- 不操作用户日常浏览器。远程调试使用独立 `--user-data-dir` 和当前可用端口，确认实例与登录态，不保存个人浏览器路径或本机工具配置。
- Zhihu++ 只能证明项目行为，不能反过来证明官方行为。
- 发布、发送、关注或删除等写操作没有授权就停在提交前。线上写入需实际管理接口和读回，seed 不算。

## 需要核对的内容

| 内容 | 检查 |
| --- | --- |
| 产品 | 文案、信息层级、操作前后状态、失败和空态 |
| 请求 | 生产代码生成的最终 URL、方法、参数、请求头、客户端、请求体和状态码 |
| 响应 | 字段类型、缺失/null、嵌套关系、分页 next 和数据来源 |
| 交互 | 返回、重试、重复操作、分页到底、切换及取消竞态 |
| 归属 | Web 通用、Android 专属、账号/灰度差异或项目适配 |

- UI 先看首屏空间、同组操作、折叠和滚动，再定尺寸。复用现有完整控件，不只抄文案；截图与官方参考核对位置、对齐和可达性。
- 创作字段要分别核对编辑器表示、草稿和发布编码；payload 数组不能证明 UI 是标签选择器。数量上限检查实际边界，不凭一次操作猜。
- 分页沿用生产触底链路，验证最终 next、去重、失败保留和重试，不为了调试交付“加载更多”按钮。
- 字段可用性按列表原字段、当前/候选 include、流程已有详情、独立 fallback 的顺序确认；分别检查原始响应和 decoder。一个数据源缺字段不能推出全部缺失。
- 知乎入站模型通过 `JsonElement` 和 `ZhihuJson.decodeJson()` 转换 `snake_case`；不手工改键、不用入站 `@SerialName` 或 `body<Model>()` 绕过生产解码。

## 样本与验证

先查相关接口和已有真实响应语料，选择能覆盖字段变体、分页和已知回归的最小样本集。测试新增与取舍按 [测试维护方法](../../../docs/testing-maintenance.md)，不固定采样配额，也不因失败次数机械翻倍。

真实响应 fixture 保留正文、转义、缺失/null、嵌套和分页形态。身份脱敏需一致且不破坏引用关系；不要手写或规范化响应来迎合模型。凭据和未脱敏原始数据保存在仓库外，不进共享文档或提交。

接口一次 200 不足以证明整条产品路径。按风险核对真实分页、失败恢复和必要的连续请求，不反复执行无关矩阵。写入成功才更新状态和计数；失败保留草稿与已有数据，取消不当失败。

实现前确认最小数据流和请求预算。复用模型、导航、分页和当前账号 client，不加薄 wrapper、重复状态或猜测性 fallback。同步记录区分成功进度与尝试时间，失败不推进进度，不阻塞首页或打断阅读。

完成时说明源码接线、实际运行结果和未验证边界。用户或真实响应推翻判断时撤销该判断及相关扩张，继续定位，不把猜测追加成永久规则。

正文划线协议按需参考 [正文划线字段](references/segment_infos.md)；只使用本次需要的部分，不重复已有证据。
