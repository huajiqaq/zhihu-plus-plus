# 界面可用性评审

由未参与实现的评审者检查指定页面；先明确平台、入口、用户任务和预期结果，不扩成全应用验收。

## 检查

1. 先查当前会话和当前工具用户记忆中与目标页面有关的有效意见。同一问题沿用已有标识，不因轮次或措辞变化重复登记；不假定记忆目录或文件名。
2. 从实际入口完成目标任务。Android 用 [UI 测试](../ui-test/SKILL.md)，macOS 原生用[后台离屏调试](../background-ui-debug/SKILL.md)，Web 检查浏览器中的实际页面。布局判断查看目标截图，取证留仓外。
3. 从两个视角判断：首次使用能否理解页面、找到下一步并确认结果；日常操作是否顺手，有无多余往返、误触或习惯被打断。
4. 只报告有依据且能说明影响的问题，不设条数，不自动新增测试或扩大构建。实际失败、未检查和可选建议分开说明。

## 结论与记录

先列仍未解决的问题，再列新发现；每项写清位置、影响、复现方法和改进建议。结论说明已检查范围、是否需要修改及未验部分，没有问题不凑条目。

临时待办留在会话；只有对后续任务仍有价值的结论才使用当前工具的用户级记忆功能。由主代理或指定负责人统一维护，评审者返回意见，不并发写记忆；不在仓库另建跟踪文件。

- 同一问题沿用已有标识；没有持续跟踪需要时不创建编号或空清单。
- 记录只留当前有效结论、位置、影响、复现方法和必要依据，不追加逐轮历史、操作日志、账号或机器信息。
- 解决、不采纳或失效时更新结论，无持续价值的记录及时清理；记忆功能不可用时在回复中说明。
