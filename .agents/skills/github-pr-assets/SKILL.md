# PR 截图与附件

只在用户要求发布或更新 PR 时上传。截图来自实际目标状态，本地路径不能作为可访问的 PR 图片链接。

## 处理

1. 用 `gh pr view <编号> --json title,body,url,headRefName,baseRefName` 读取现有 PR。
2. 核对文件、图像尺寸和画面。优先复用已经验证的最终截图，不为上传重新搭设备或制造测试。
3. 使用现有持久链接，或用户允许的资产仓库/托管位置。没有可用位置时报告或询问，不自动创建公开仓库，不把临时图塞进产品源码。
4. 路径按项目和 PR 区分，文件名说明内容。验证 URL 的 HTTP 状态与图片类型。
5. 正文用临时文件和 `gh pr edit <编号> --body-file <文件>` 更新，避免把 `\\n` 原样发送。读回正文，核对图片、分支、语言及说明。

## 来源与隐私

- 写明截图来自实际 APK、AVD 或可复现的 UI 渲染，以及它证明的状态。
- 远端头像、封面等产品资源使用真实响应 URL；加载失败就说明，不能生成图片冒充真实数据链路。
- 真实账号、Cookie、私信和私人内容不上传。使用脱敏或获准的测试数据，不把隐私清理变成修改协议字段。
- 涉及数量边界或折叠时覆盖实际变化的分支，不用同一帧改文件名冒充多个状态。
- 无浏览器授权时不导航、聚焦或上传到用户日常标签页。

普通 issue/comment REST API 只接收 Markdown，不提供通用截图附件上传接口；`uploads.github.com` 的 release 上传也不是 PR 图片上传。不要把未经验证的内部 Web 上传流程包装成 `gh api` 用法。

链接 404 时核对 owner、repo、branch、路径和是否已发布。PR 仍显示旧内容时先读回服务端正文，不凭浏览器缓存判断。只修改本次资产和正文，保留工作树中的其他改动。
