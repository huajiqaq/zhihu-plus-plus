# 性能与行为回归

同时保住行为和性能，不默认恢复旧实现，也不因为代码更短就保留当前优化。

## 定位

- 对照用户给出的正确版本和实际回归路径，确认被破坏的行为，而不是以现有实现或测试预期证明自己正确。
- 优先复用已有回归和测量。缺证据且成本合理时，做一次修复前失败、修复后通过；不为形式重建多变体或重复取证。
- 查缓存保存的对象、真实所有者和失效条件：内容、宽度、字体、主题、离屏、导航及进程重建。
- 区分存活组合中的复用、回收后重建和用户完整操作。高度缓存不等于内容布局缓存，对象复用也不等于没有测量或绘制成本。

## 测量

按真实输入分开测转换、结构构建、文本/公式测量、布局、绘制和目标交互。预热后在同一环境采样，比较中位数与分布，不用预构造结果、跳过绘制或最好一次数字冒充改善。

能由 Compose JVM 证明的行为先用 JVM。Android 只校准同输入的量级或检查平台行为，不把软件 GPU 的 AVD 倍率当成所有手机门槛。

## 取舍

先判断自然的完整实现是否有有效缓存；确需惰性布局时，把完整数据能力与当前可见布局分开。按需布局完整内容需要测触发延迟，不能用不可见 UI、时序等待或额外状态伪造行为。

已有真实数据证明全量布局会卡顿或 OOM 时，保留这条性能边界，但不从缓存类推断当前正式 API 已支持惰性布局，也不默认恢复旧实现或接入候选。未来确需回收时保留完整 AST/IR、同一选择源及内容与环境失效规则。长按、手柄、全选、滚动和可见工具栏复制共用同一选择源，不能只修复制字符串而丢掉范围和手柄。

框架缺少公开表达能力时，可保留窄范围且有行为与性能验证的桥接；注释写明具体框架边界，不扩成通用绕过方案。

列表重排动画先检查稳定 key 和直接 item 根节点：`animateItem` 放在内部卡片不能驱动兄弟 item 的位移。

## 验收

用受影响的长内容、离屏部分和连续操作复测，不删正常操作来缩窄失败。滚动目标须实际进入容器的裁剪视口，节点存在不等于可见；屏外节点可保留或回收。选择按长按、滚离、返回高亮与手柄、点击可见工具栏复制的完整流程验证，不强求点击屏外菜单；涉及特殊行内节点时检查跨入和跨出。

审查功能、滚离返回及目标交互的可比较结果；实际采用回收时再检查重建。保留真实首帧解析、布局、绘制及长滚动性能覆盖，去掉实现绑定断言、薄包装和猜测分支。按用户预算执行构建与测试，报告实际结果和未验证项；不把静态审查、编译或截图非空当成行为通过，也不改写原失败日志。
